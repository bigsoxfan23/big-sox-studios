## Forward ordering and manual reconciliation

The D1 batch atomically claims dedupe and creates/attaches the case, message and initial job. A losing/replayed claim has no writes or forward. Before invoking external forwarding, the handler durably changes `claimed` to `UNKNOWN`. Only a resolved forward followed by a successful D1 update records `forwarded`. This indicates API acceptance, not Gmail inbox delivery.

Forwarding and D1 cannot be atomic. Crashes before invocation can leave `claimed`/UNKNOWN with no forward; crashes after successful forwarding can leave UNKNOWN with a delivered original. Every existing receipt suppresses automatic forwarding, regardless of state. After claim, errors are swallowed without SMTP rejection to avoid provoking unsafe retries. Before claim, invalid input/storage failure rejects with a fixed message. A crash between transaction commit and claim verification can also leave a durable claim and a rejection; a later event is suppressed. This deliberately favors duplicate prevention over guaranteed delivery.

After future owner approval, an operator must inspect private receipts with `forward_state IN ('claimed','UNKNOWN')`, correlate Cloudflare forwarding evidence and Gmail, and record a reviewed outcome. Never reset a receipt, delete its key, or automatically replay a forward. Without decisive evidence, retain UNKNOWN. If evidence establishes no forward, any manual recovery requires separate owner approval and an audit trail. Owner-authenticated GET `/api/inbound-status` returns only `{available:true, unresolved:N}` for claimed/UNKNOWN receipts, with no-store and no identifiers/PII or mutations. Before 0002 it returns `{available:false, unresolved:null}` via a schema presence check; storage errors return a fixed 503, never a false zero. There is no UI polling or alerting: owner must check it manually. No reconciliation/resend HTTP endpoint, scheduled recovery, or automatic retention is included. Receipt metadata is private PII and needs an approved retention policy; preserve replay-suppression tombstones if redacting.
